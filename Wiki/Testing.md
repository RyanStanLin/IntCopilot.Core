# 测试规范与验证范围

默认 `swift test` 仅使用本地、关联一致的脱敏 fixtures 和注入 mock。CI 不读取真实账号，不连接平台。原始 research、密码、Token、Cookie、真人资料和私人附件地址均不提交。

响应测试覆盖全部 JSON 抓包的强类型解码及精确 JSON 往返。请求 fixture 覆盖所有原始请求，包括无响应或非 JSON 的认证/打印记录；认证由专用流程测试，业务请求由目录和编码 mock 测试。发现接口的路由与元数据测试只证明 SDK 编码行为，不证明实际服务端契约。

认证验证包含两平台密码登录、平台 Token、教师 SSO、OAuth 审批、验证码错误重试、过期/限流、显式重发、并发续期、自动重登预算、回调、会话快照和登出竞态。业务测试验证请假依赖、学校隔离、时间单位、空响应、只读最多重放一次、写入不重放、新字段、同码异义及 SOP 参数传递。

CI 分别运行 macOS mock 测试、Release 编译，以及 macOS、iOS、iOS Simulator、Mac Catalyst、tvOS、watchOS、visionOS 编译。成功与失败均以 GitHub Actions 实际记录为准，不能把没有 Xcode 的本机 Swift 编译当成所有 Apple SDK 的验证。

真实测试仅使用已明确确认的只读操作和专用认证流程。教师测试只能使用账号持有人指定的唯一课程和学生；具体身份保存在本地审批上下文，不进入公共 fixture。任何写入或可能触发消息的操作在实施前逐项获得授权。不能可靠撤回时只能 mock。

`Tools/audit_public_artifacts.py` 检查敏感路径、JWT、私有资源 URL、认证头和常见凭据模式；发布前额外传入私有 captures，检查真实秘密是否出现在待发布文件中。不要把审计失败的敏感值打印出来。

数据契约版本参考抓包与公开前端脚本版本，而非平台官方稳定性承诺。空列表、静态推断和只读观察的验证范围必须单独记录。新增 API 指南说明如何扩大覆盖而不产生真实业务副作用。
